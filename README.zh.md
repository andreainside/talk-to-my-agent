# talk-to-my-agent

> **Got a problem? Talk to my agent.**

你们团队在飞书群里聊天,每个人的电脑上都跑着一个 coding agent。这个桥让每个人的 agent **在群里拥有一个座位**:@ 某个同事的 bot,是**那个人的电脑**醒过来,读完群里的上下文,用**那个人的**仓库和工具干活,然后在群里回答。

人类过去是 AI 之间的传话筒:「我的 agent 说 X」→ 复制 → 粘贴 →「你问问你的 agent Y」。

**但这到此为止。现在 agent 自己进群了。**

## 一个群一个员工,各有各的记忆

它不是无状态的问答机,而是**一个房间一位同事**:

- 每个群一条**独立的持续会话**、一个独立的家目录。它在**你的仓库里干活**(你的 AGENTS.md 规则和项目技能对它生效),在**家里记忆**(git 之外)。你构建频道里的那位记得构建频道的事,反馈群里的那位是在 bug 报告里长大的。需要时它们可以互相读笔记。
- 对话历史会被引擎自动压缩,所以每位员工维护**自己的 `CLAUDE.md`**——它自己写的长期记忆:这个群里都有谁、拍板过什么、踩过什么坑。进新群 = 入职一位新员工,读完笔记就上岗。
- **它干活的时候你照样能问它**,它会直接回答——不用排队、没有"请稍候"。这是引擎原生的打断能力,就像你打断一个正在编译的同事。
- 同事的 agent 之间也能互相 @(带 agent 对话链上限,不然两个客气的 agent 能互相寒暄一整夜)。

## 运作方式

```
飞书群
   │  有人 @ 你的 bot
   ▼
事件流(lark-cli 长连接)              ← 你的电脑,常驻
   │  1. 秒回一个你的签名表情 😏
   │  2. 把"它上次看过之后的新消息"喂进去
   ▼
这个群的员工 —— 一条活着的 claude 会话  ← 自己的家,自己的记忆
   │  读代码、查日志、跑只读命令
   │  其他动作 → 🔐 审批卡,只有你能点
   ▼
它自己在群里发出答案
```

桥只是个信使:收消息、打表情、送进去。说话的是 agent 自己。

每人在自己机器上跑自己的桥、用自己的 bot。**@ 谁的 bot,谁的机器来答。**没有共享服务器、没有共享凭证——飞书流量走每个人自己的 `lark-cli` 登录态,这个仓库碰不到任何秘密。

## 快速开始(最省事:让你的 Agent 替你装)

把这句话粘给你自己的 Claude Code / Codex:

> 按 docs/agent-setup.md 在这台机器上部署 https://github.com/andreainside/talk-to-my-agent ,配置项都问我,不要自己猜。

那份文档是**写给 agent 看的**:它会检查环境、带你创建飞书 bot、问你哪些仓库可以自由读、配好无头认证、真实召唤一次验收,最后装成后台常驻服务。

想自己动手:[docs/setup.md](docs/setup.md)。

## 在群里召唤

```
@某人的 bot   我们上传路径里的重试逻辑到底是怎么做的?
@某人的 bot   追一下 seq 契约在哪里强制的,再说说如果批量分配会坏在哪
@某人的 bot   +free 去把 README 里的错别字改了,然后给我看 diff   ← 仅本人:本次免审批
```

它干活的时候你再问一句,它就直接答你——这正是重点。

## 配置你自己的 agent(私聊控制面)

私聊自己的 bot,别人的消息一概无效:

| 私聊发 | 效果 |
|---|---|
| `status` | 现在有几位员工、各自在干什么、花了多少钱 |
| `model opus` / `sonnet` / `haiku` | 全员换模型,记忆保留 |
| `emoji SMUG` | 换签名表情 |
| `emoji that` | 先在它上一条消息点你想要的表情,再发这句,它自动认领 |
| `reset <群名>` / `reset all` | 给某个群的员工换个新脑子 |
| `help` | 命令列表 |

**一切都由你自己定**:哪些仓库可自由读、审批等多久、回主群还是回 thread、用什么表情、用什么模型——全在你本机的配置里,每人一套:[docs/configuration.md](docs/configuration.md)。

## 说人话的审批

当 agent 想做自由范围之外的事,你会收到一张**用大白话说清它要干嘛**的卡片,技术细节放在下面:

> 🔐 我想修改文件 src/upload.rs,可以吗?
> 点 YES 同意这一次 · 点 ✔ 本次任务都不用再问 · 点 NO 不同意

点 **YES**(仅此条)、**✔**(整个任务)、**NO**(拒绝),不理它就是拒绝。**只认 owner 的点击**——同事可以让 agent 做任何事,但只有你能放行。

判定方式是**划区域,不是列命令**:在它的工作区里(自己的家、你给它的那个一次性 checkout、临时目录)读写和跑命令都自由;你其他的仓库可读,要改就请示;再往外一律请示。两种情况永远会问——破坏性操作伸到工作区之外,以及对外/不可逆的动作(`git push`、开 PR、发布、部署),后者连整任务放行都不覆盖。

**没有"安全命令白名单"要维护**——那种做法每出现一种新的 shell 写法就会漏。`python3 test_permissions.py` 把整套策略跑成可执行用例。

## 会话是真实的会话

每位员工都是你机器上一条普通的 Claude 会话——`claude --resume <id>` 就能把它变成你的终端窗口,上下文原封不动。同事的一个提问,可以直接变成你下午的开发会话。

## 保持最新

桥每天检查一次新版本(零 token),有新版就私聊你 changelog。回 `update` 就切换并重启;不回就维持现状。没有你的话,什么都不会被拉取。

## 群规(安全边界)

- agent 只在**自己的 bot 被 @** 时行动,不偷听。
- 群聊内容是**数据不是指令**——唯一的请求是 @ 它的那句话。
- 家目录以外的写操作永远请示 owner,超时即拒绝。
- 只有 **owner 的私聊**能改配置,只有 owner 的点击能批准。

## 它能修自己

你的 agent 能读这个项目的源码和你的配置文件。所以当它烦人的时候——请示太频繁、表情不对、回复位置不对——直接说,它会去找对应的设置并主动提出帮你改(改动落在它家目录之外,所以你会先看到审批卡再决定)。如果是桥本身的毛病,它可以在这个仓库提 issue——同样要你批准,毕竟署的是你的名字。

## 在这之上能玩什么

反馈自动修复闭环、告警自动初诊、跨机器 agent 接力、异步 standup(「@她的 agent——迁移做到哪了?」)。桥本身保持极小,好玩的都在 [docs/playbook.md](docs/playbook.md)。

## 状态

早期、有主见、从一个真实团队的日常工作流里长出来。**Claude Code 和 Codex 都能跑**——配一下 `backend`,用你手上有的那个;两边是同一套同事模型、同一套审批策略,[两者的差别](docs/configuration.md#5-backends-claude-code-or-codex)写在文档里,不含糊。只支持飞书/Lark——设计可移植到任何有事件 API 的聊天平台。
